## 1. Load test (SPEC §13, §14.3)

`prompt-battle-api/scripts/loadtest.sh` (wraps `scripts/LoadTest.java`, JDK only) ran against the API jar on the `fake` profile (`localhost:18080`).

**Setup of every run:**
- 2 cities × 50 phones × 3 attempts, within a 120 s window.
- Every phone polls `/api/me` every 1.5 s with `If-None-Match`, from the start. The stages poll every 1.5 s and the admins every 2 s, about 75 requests/s in total (SPEC: about 70).
- The first "Generate" is spread over 30 s, with 5–20 s between attempts. `ramp 0` means all 100 at once.
- Both cities close at the same moment.

**How latency is measured:** from "Generate" until a poll shows the image. So it includes up to 1.5 s of polling delay, and 1.5 s of generation shows as about 3.0 s.

### Event configuration: one provider with BFL's 24 slots (D-027), final jar

| Fake latency | Arrivals | p50 | p95 | max | close → scored | errors | Gates |
|---|---|---|---|---|---|---|---|
| 1.5 s | realistic | 3.03 s | 3.20 s | 3.31 s | 0.26 s | 0 | PASS |
| 1.5 s | all at once | 3.05 s | 6.56 s | 9.59 s | ≤ 0.27 s | 0 | PASS |
| 3.0 s | realistic | 4.54 s | 4.58 s | 6.08 s | 0.27 s | 0 | PASS |
| 3.0 s | all at once | 4.57 s | 12.51 s | 17.04 s | 0.26 s | 0 | PASS |

**Gates** (exit code 0): every attempt done within 120 s, p95 ≤ 15 s, close → scored ≤ 15 s, and no errors.

**Worst case:** all 100 players at once with 3 s per image puts Bogotá's own p95 at 14.0 s, just under the 15 s gate. Real arrivals are softer (players type first).

### Earlier configurations (same day, before D-027)

### Fixed (each with a test that fails without the fix)

**API:**
- **QUEUED without a queue position.** A `QUEUED` attempt that already left the FIFO now shows as `GENERATING`. The dispatcher keeps it "started" until the domain has applied its result (`AttemptAccountingTest`, `QueueFairnessTest`). The load test confirmed it: the final runs saw no `QUEUED` poll without a position.
- **A hidden entry came back** when its player selected that image again. The hide is now kept on the attempt (`RankingTest`).
- **A failed prefetch failed scoring.** Scoring that joined a failed best-effort prefetch now redoes the embedding call, instead of failing the try and possibly switching to the backup (`DeterminismCheckTest`).
- **Dispatcher robustness.**
  - A provider throwing an `Error` used to leak its slot forever. The slot is now released and the job completed whatever happens.
  - A job id still running is no longer accepted a second time.
- **Simulation coverage.** The simulation now asserts that the stage shows no player image or nickname while closing, after scoring and at mini-podium step 0 (`TwoCitySimulationTest`).
- **Load test.**
  - It prints the server's chain, split and per-provider limits (proof of the §14.3 condition).
  - Phones poll from the start.
  - It no longer waits forever on a deleted round, and a missing option value prints the usage.
- **`fake2`** shows its model in `/api/admin/providers`.

**UI:**
- **Blocking: admin section links loaded the landing page.** A bare `#fragment` resolves against `<base href>`. Links now use the console's own URL. Sections take focus and land below the sticky bar (`e2e/admin.spec.ts` "section links").
- **A stale admin poll undid "Next".** A poll that started before an action's response could put the previous step back, inviting a second tap. It is now dropped (`admin-state.service.spec.ts`).
- **A confirmed action was silently dropped.** A confirmed Close round or Restart reveal during another action used to close the dialog without sending anything. It now waits for the action in flight (`admin-state.service.spec.ts`).
- **The entries round picker** snapped back to the current round on every poll. It now keeps the admin's pick.
- **`/api/admin/me` had no timeout,** so a stalled request left the console on "checking" forever. It now has 15 s, like the other admin calls.
- **"Iniciar mini-podio" [Start mini-podium]** now shows only when the API offers a mini-podium. The fake backend now sends the live mini-podium preview in `ROUND_SCORED`, as the API does, which closes the I1 known gap.
- **A first-load network failure was a dead end.** The error page now offers "Reintentar" [Try again], but not for `CITY_NOT_FOUND` (`error-page.spec.ts`).

### Not fixed, with the reason

**API:**
- **QUEUED without a position while a prompt is prepared.** With `PROMPT_LLM_MODERATION` or `PROMPT_TRANSLATE_TO_EN` on, an attempt is `QUEUED` with a null position until it enters the FIFO, and the POST reply can carry a null position.
  - **Why not fixed:** both flags are off by default, and the UI shows "waiting in queue" without a number. Recorded in D-027 #5.
  - **If the dry run turns translation on,** decide whether API.md §5 should allow null there.
- **AI comments after a restart.** A restart while podium comments are still being written loses them: the canned ones are used. **Why not fixed:** a graceful fallback, and a rare case.
- **Restoring with the mini-podium switched off.** Restoring a snapshot taken with `MINI_PODIUM_ENABLED=true` and restarting with `false` asks for unused mini comments. **Why not fixed:** nobody changes that flag during the event.
- **A late cancel with the LLM flags on.** An attempt cancelled at the end of grace can still be generated once and then discarded. **Why not fixed:** the flags are off.
- **A double submit.** A connection reset right after a submit was accepted can submit the image twice and bill it twice. **Why not fixed:** a rare, venue-network edge with a cost of cents. Changing the retry rules at the freeze is riskier than the cost.
- **The fake load test doesn't prove close → results ≤ 15 s.** **Why not fixed:** this needs the live services; it is in the runbook's dry-run and `--real` checks.

**UI:**
- **Which preview shows in `ROUND_SCORED`.** The control panel shows the final-podium preview there, not the mini-podium's top 3. **Why not fixed:** the admin can check and hide the round's entries in "Entregas" [Entries] (runbook §5). Showing both would change the admin layout at the freeze.
- **No confetti after a replayed reveal.** After "Reiniciar revelación" [Restart reveal], #1's confetti doesn't fire again. **Why not fixed:** cosmetic.
