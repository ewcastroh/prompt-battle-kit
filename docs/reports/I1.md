## 2. Contract check (UI ↔ API)

The UI already switched between the fake and the real API only through the `fake` build configuration (D-017), so the default and production builds call the API from `config.json`; nothing had to be rewired. Checks:
- Every UI call (`AdminApi`, `PlayerApi`, stage, player state) matches a controller mapping, method and status code.
- A full event through the real UI (§3) with every API response ≥ 400, failed request and console error recorded: **none**.
- The JSON of every admin, stage and player read endpoint diffed against `api.models.ts` (keys and nullability, nested), instants (milliseconds, `Z`), ETag 304, QR, unknown image 404.

Found and fixed (API.md **1.4**, no API change):
1. **`podium.roundId`.** API.md §7 said the admin state's `podium` has no `roundId`; the API sends `roundId: null`, as API.md §1 requires ("fields that don't apply are present with `null`"). **API.md was wrong.** Fixed the text; `PodiumState` now has `roundId: string | null`, and the fake sends it.
2. **Preview order** was unspecified. The API lists `preview` in reveal order (rank `size` first), like the stage's `entries`; the fake listed rank 1 first, so the admin table read in the opposite order against the real API. Written into API.md; the fake now matches.
3. **When `podium` is non-null** was unspecified. The API returns it once the city has a `SCORED` run (even with `size` 0); the fake waited for `size` > 0. Written into API.md; the fake now matches.

Known and left: the fake's `miniPodium` is `null` in `ROUND_SCORED`, where the API sends a live preview. The UI reads `miniPodium` only in `MINI_PODIUM`, so nothing shows the difference.

## 3. Two-city event (Compose, `fake` profile)

`npm run e2e:compose` (UI repo, `e2e/compose/event.compose.ts`): two stages (1920×1080), two admin consoles (1366 px), two phones (360×800) and two HTTP players per city. Medellín runs in Spanish/light, Bogotá in English/dark. Every action goes through the real admin and player screens.

Flow: event reset → rounds created from the admin (practice and round 1 generated from a prompt in Medellín; round 2 an **uploaded** JPEG from Bogotá, multipart) → calibrations `READY` → 8 players join → practice in both cities, practice gallery on Medellín's stage → rounds 1 and 2 in both cities (+60 s in Medellín), closed with confirmation, scored → Medellín plays the mini-podium after each round, Bogotá skips it → final podium in both cities, revealed 4 → 1, then the original prompts → phones show their final rank → results CSV downloaded from each admin.

Result: **passed in 2.7 min**, no API errors, failed requests or console errors on any of the 10 pages. Bogotá's stage never showed a Medellín player.

## 5. Findings for the owner

- **Parent `.env` has an empty numeric value.** `docker compose up` crash-loops the API with `Failed to bind properties under 'app.gemini.embedding-rpm'` because `GEMINI_EMBEDDING_RPM=` is blank: `${GEMINI_EMBEDDING_RPM:90}` falls back only when the variable is unset, not when it is empty. Fix: delete the empty lines (or copy the values from `.env.example`). The same applies to Railway: don't save a variable with an empty value. The test run above used its own environment instead of `.env`.
- **Run `./mvnw verify` with the IDE's Java build idle.** One local run failed with `forbidden-models.txt` missing from `target/classes` because the VS Code Java extension rebuilt `target/` mid-run; the re-run passed.
